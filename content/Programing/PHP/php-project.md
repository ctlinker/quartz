# PHP Project Layout

---

# Typical Project Structure

A modern PHP application usually separates **public files** (accessible from the browser) from **application code** (private).

```text
my-project/
├── app/
│   ├── Controllers/
│   ├── Models/
│   ├── Services/
│   ├── Middleware/
│   └── Views/
│
├── config/
│   ├── app.php
│   ├── database.php
│   └── routes.php
│
├── storage/
│   ├── logs/
│   ├── cache/
│   └── uploads/
│
├── vendor/
│
├── public/
│   ├── index.php
│   ├── .htaccess
│   ├── css/
│   ├── js/
│   └── images/
│
├── composer.json
├── composer.lock
├── .env
├── .env.example
└── README.md
```

Only **`public/`** should be exposed by the web server.

Everything else should remain inaccessible.

---

# The Entry Point

Almost every modern PHP framework has a **single entry point**.

```
Browser
    │
    ▼
public/index.php
    │
    ▼
Application
    │
    ▼
Controller
    │
    ▼
Response
```

Every request eventually goes through

```text
public/index.php
```

This is called the **Front Controller Pattern**.

---

# public/

The only directory Apache or Nginx should serve.

```
public/
├── index.php
├── .htaccess
├── favicon.ico
├── css/
├── js/
└── images/
```

Contains

- static assets
    
- entry point
    
- rewrite rules
    

Never place application code here.

---

# index.php

Responsible for bootstrapping the application.

Typical flow

```text
Request
    │
    ▼
Load Composer

Load Environment

Load Configuration

Register Routes

Execute Router

Return Response
```

Example

```php
<?php

declare(strict_types=1);

require __DIR__ . '/../vendor/autoload.php';

$app = new App\Application();

$app->run();
```

Most frameworks differ only in what happens after loading Composer.

---

# .htaccess

Routes every request to `index.php`.

```apache
RewriteEngine On

RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d

RewriteRule ^ index.php [L,QSA]
```

Meaning

If the requested resource

- isn't a file
    
- isn't a directory
    

Apache executes

```text
index.php
```

instead.

This allows URLs like

```
/users
/users/15
/blog/php-routing
```

without actual files existing.

---

# composer.json

Defines

- project metadata
    
- dependencies
    
- autoloading
    
- scripts
    

Example

```json
{
    "name": "acme/blog",

    "require": {
        "slim/slim": "^4.0",
        "vlucas/phpdotenv": "^5.6"
    },

    "autoload": {
        "psr-4": {
            "App\\": "app/"
        }
    }
}
```

Install dependencies

```bash
composer install
```

Add a dependency

```bash
composer require slim/slim
```

Generate autoloader

```bash
composer dump-autoload
```

---

# vendor/

Automatically generated by Composer.

```
vendor/
├── autoload.php
├── composer/
└── ...
```

Never edit manually.

Usually ignored by Git if dependencies are installed during deployment.

---

# Composer Autoloading

Instead of

```php
require "User.php";
require "Database.php";
require "Router.php";
```

Use

```php
require "../vendor/autoload.php";
```

Composer loads classes automatically using **PSR-4**.

Example

```
app/

└── Models/
    └── User.php
```

```php
namespace App\Models;

class User
{
}
```

Usage

```php
use App\Models\User;

$user = new User();
```

No manual `require`.

# Environment Variables

Never hardcode secrets.

Use

```
.env
```

Example

```
APP_ENV=development

DB_HOST=localhost

DB_NAME=blog

DB_USER=root

DB_PASSWORD=secret
```

Load using Dotenv

```php
$dotenv = Dotenv\Dotenv::createImmutable(__DIR__ . "/..");

$dotenv->load();
```

Access

```php
$_ENV["DB_HOST"];
```

# Routing

The router decides which controller handles the request.

```
GET /users
      │
      ▼
UsersController@index
```

Example

```php
$router->get("/users", UsersController::class);
```

---

# Controllers

Receive HTTP requests.

```
Controller

↓

Validate

↓

Call Service

↓

Return Response
```

Example

```php
class UserController
{
    public function show(int $id)
    {
        //
    }
}
```

Controllers should remain thin.

---

# Services

Contain business logic.

```
Controller

↓

Service

↓

Repository

↓

Database
```

Example

```php
class UserService
{
    public function register(array $data)
    {
    }
}
```

---

# Models

Represent application data.

Example

```php
class User
{
    public int $id;

    public string $name;
}
```

May also interact with the database if using an ORM.

---

# Views

Contain presentation.

```
views/

home.php

login.php

dashboard.php
```

Should contain little or no business logic.

# Storage

```
storage/

logs/

cache/

uploads/
```

Used for

- logs
    
- temporary files
    
- uploaded files
    
- cache
    

Should not be publicly accessible.

# Best Practices

- Keep **`public/`** as the web root.
    
- Route all requests through **`index.php`** (Front Controller).
    
- Let **Composer** manage dependencies and autoloading.
    
- Keep secrets in **`.env`**, never in Git.
    
- Separate controllers, services, models, and views.
    
- Never expose `vendor/`, `app/`, `config/`, or `.env` to the web.
    
- Use PSR-4 autoloading and namespaces instead of manual `require` statements.

This layout is the foundation used by most modern PHP frameworks (Slim, Laravel, Symfony, Laminas, etc.), even though each framework adds its own conventions and tooling on top.
